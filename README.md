# Binary Bomb Lab — GDB 调试通关教程

> 本教程面向零基础同学，手把手教你用 GDB 调试器逐关破解二进制炸弹。
> 建议分窗同时观看反汇编代码
> 学号示例：720028（你的学号会不同，但方法通用）

---

## 0. 准备工作

### 运行炸弹

```bash
./bomb_linux 720028                # 交互模式，手动输入答案
./bomb_linux 720028 < bomb_720028.txt  # 从文件读取答案
```

炸弹从 `bomb_<学号>.txt` 逐行读取答案，一行对应一个关卡。答错就爆炸退出。


### 关键概念：随机种子

炸弹用你的学号作为随机种子，所以**同一个学号每次运行产生的随机数序列完全相同**。不同学号会进入不同的子关卡。

## 1. GDB 速查表

只需要掌握这几个命令就能通关：

```gdb
# 启动
gdb ./bomb_linux

# 运行
run 720028                    # 交互运行
run 720028 < bomb_720028.txt  # 从文件运行

# 断点
break phase_1                 # 在函数入口断点
break *0x401b7d               # 在指定地址断点（注意星号）
delete                        # 删掉所有断点

# 执行
continue    # 继续运行到下一个断点
stepi       # 执行一条汇编指令（进入函数）
nexti       # 执行一条汇编指令（跳过函数调用）

# 查看内存（最常用）
x/s $rdi            # 把 rdi 当作字符串指针，打印字符串
x/s $rsi            # 同上，看 rsi
x/6d $rsp           # 从栈顶开始打印 6 个十进制整数
x/d 0x408820        # 打印指定地址的一个十进制整数
x/5i 0x401b53       # 打印指定地址的 5 条汇编指令

# 查看寄存器
info registers       # 看所有寄存器
print $rax           # 看 rax 的值
print/x $rax         # 看 rax 的十六进制值

# 查看全局变量 rand_div（超高频使用！）
p *(long long*)0x408820

# 反汇编
disas phase_1        # 反汇编整个函数
```

## 2. 调用约定（读汇编前必看）

x86-64 函数调用的参数传递规则：

| 参数位置 | 寄存器 | 用途举例 |
|---------|--------|---------|
| 第 1 个 | `%rdi` | `phase_1(input)` 中的 `input` 指针 |
| 第 2 个 | `%rsi` | `strcmp(a, b)` 中的 `b` |
| 返回值  | `%rax` | 函数返回值存这里 |

**实战意义**：断点命中时，`%rdi` 通常就是你的输入，`%rsi` 经常藏着程序生成的秘密字符串。

---

## Phase 1：读秘密字符串

### 目标

程序生成了一个随机字符串，要求你输入一模一样的。

### GDB 操作

```gdb
$ gdb ./bomb_linux
(gdb) break *0x401b7d
(gdb) run 720028
请输入第1级的密码：（随便输入 test 回车）
```

断点命中，此时程序正准备调用 `strcmp`，`%rdi` 是你的输入，`%rsi` 是秘密字符串：

```gdb
(gdb) x/s $rsi
0x7fffffffd695: "yxYZRkQzJt"
```

拿到答案了！写入 `bomb_720028.txt` 第一行：

```
yxYZRkQzJt
```

### 原理

断点设在 `strcmp` 调用之前。此时两个参数已经就绪：
- `%rdi`（第1个参数）= 你的输入
- `%rsi`（第2个参数）= 程序生成的随机字符串

`x/s` 命令把内存内容当字符串打印出来，一步搞定。

## Phase 2：六个递增的整数

### 目标

输入 6 个整数，满足特定约束。程序根据学号随机选择子关卡。

### 第一步：找到进入了哪个子关卡

更新答案文件（加入 phase 1 答案），加一行占位 `1 2 3 4 5 6`，然后：

```gdb
(gdb) delete
(gdb) break *0x401bb3
(gdb) run 720028 < bomb_720028.txt
```

断点命中后查看随机分发结果：

```gdb
(gdb) p *(long long*)0x408820
$1 = 13
```

`rand_div = 13` → 进入了 `phase_2_13`。

> **地址 0x408820 是什么？** 它是全局变量 `rand_div`，每次调用 `GenerateRandomNumber()` 后结果都存在这里。这是整个实验中你查得最多的地址。

### 第二步：分析子关卡的约束

查看 `phase_2_13` 的反汇编：

```gdb
(gdb) disas phase_2_13
```

逐段阅读，找到关键约束。对照反汇编，可以总结出：

1. **首元素约束**：调了 `GenerateRandomNumber(50)`，结果 +16 就是 `a[0]`
2. **非负约束**：循环检查 `a[i] >= 0`
3. **递增约束**：循环检查 `a[i] > a[i-1]`

### 第三步：提取首元素的值

```gdb
(gdb) break *0x4026b0
(gdb) run 720028 < bomb_720028.txt
(gdb) p *(long long*)0x408820
$2 = 28
```

`a[0] = 28 + 16 = 44`。需要 6 个严格递增的正整数，首元素 44：

```
44 45 46 47 48 49
```

写入答案文件第二行。

## Phase 3：数字 + 字符 + 数字

### 目标

输入格式：`数字 字符 数字`（如 `133 E 106`），需要匹配程序生成的三个值。

### 第一步：确定子关卡

```gdb
(gdb) delete
(gdb) break *0x4028b4
(gdb) run 720028 < bomb_720028.txt
(gdb) p *(long long*)0x408820
$3 = 13
```

进入 `phase_3_13`。

### 第二步：提取第一个数字 (val1)

子关卡里会再调一次 `GenerateRandomNumber(8)`，结果 +130 就是 val1：

```gdb
(gdb) break *0x40421f
(gdb) run 720028 < bomb_720028.txt
(gdb) p *(long long*)0x408820
$4 = 3
```

`val1 = 3 + 130 = 133`

### 第三步：提取字符 (ch) 和第二个数字 (val2)

在子关卡的 switch-case 中，程序通过随机数生成期望的字符和数字。

```gdb
(gdb) break *0x404383    # 设置期望字符的指令
(gdb) run 720028 < bomb_720028.txt
(gdb) printf "%c\n", $al
E
```

再断点查看 val2 的期望值：

```gdb
(gdb) break *0x404390
(gdb) continue
(gdb) p *(long long*)0x408820
$5 = 106
```

**答案**：`133 E 106`

### 原理

`sscanf(input, "%d %c %d", &val1, &ch, &val2)` 解析三个字段。程序内部用 `switch(val1 - 130)` 分支来决定期望的字符和数字，每个分支都会调随机数。你在对应分支的代码处设断点，直接读出期望值。

## Phase 4：阶乘查表

### 目标

输入一个整数 x，程序做 `x/500` 取商，算商的阶乘，然后和表中的值比较。

### 第一步：确定子关卡（小心跳转表陷阱！）

```gdb
(gdb) delete
(gdb) break *0x404604
(gdb) run 720028 < bomb_720028.txt
```

**这一步很关键**：`rand_div` 的值不一定等于子关卡编号！必须查看实际跳转目标：

```gdb
(gdb) x/i $rax
0x4046ec <phase_4+305>: mov -0x8(%rbp),%rax
```

跳到 0x4046ec，看它调了哪个函数：

```gdb
(gdb) x/3i 0x4046ec
0x4046ec: mov -0x8(%rbp),%rax
0x4046f0: mov %rax,%rdi
0x4046f3: call 0x40548f <phase_4_24>
```

进入 `phase_4_24`。

### 第二步：理解算法

阅读 `phase_4_24` 的反汇编（`disas phase_4_24`），核心逻辑：

1. 读一个整数 x，要求 x > 499
2. `quotient = x / 500`（编译器用魔数乘法优化了除法）
3. `func4_2(quotient)` 就是求 quotient 的阶乘
4. 阶乘结果必须等于表中某个值

表的内容（从反汇编中直接读出）：

| 索引 | 值 | 含义 |
|------|------|------|
| 0 | 24 | 4! |
| 1 | 120 | 5! |
| 2 | 720 | 6! |
| 3 | 5040 | 7! |
| 4 | 40320 | 8! |
| 5 | 362880 | 9! |
| 6 | 3628800 | 10! |

### 第三步：GDB 提取并求解

```gdb
(gdb) break *0x40554a
(gdb) run 720028 < bomb_720028.txt
(gdb) p *(long long*)0x408820
$1 = 5
```

`rand_div = 5`，查表 `table[5] = 362880 = 9!`

反推：

```
需要：quotient! = 9!  →  quotient = 9
又：quotient = x / 500
所以：x = 9 × 500 = 4500
验证：4500 > 499 ✓
```

**答案**：`4500`

## Phase 5：注入 Shellcode（不可能任务）

### 这关在干什么？

前四关你输入的是"数据"，程序拿你的数据做判断。第五关完全不同：**程序把你输入的十六进制字符串翻译成字节，然后让 CPU 直接执行这些字节当指令**。

```
你输入的 hex 字符串  →  tohex() 翻译成字节  →  CPU 跳过去执行
"bf00040000..."          buf = [0xbf, 0x00, ...]    mov edi, 0x400
```

这就是"数据即代码"——冯·诺依曼架构的核心思想。

### 第一步：回答 Y 进入

答案文件第 5 行写 `Y`。

### 第二步：理解检查流程

程序对输入做了三道检查：

1. **长度检查**：hex 字符串长度 10~768（即 5~384 字节机器码）
2. **XOR 校验**：buf 的 256 字节逐个异或，结果必须等于 `rand_div & 0xFF`
3. **超时检查**：执行时间 ≤ 1000ms

### 第三步：确定 XOR 目标

```gdb
(gdb) break *0x401808
(gdb) run 720028 < bomb_720028.txt
(gdb) p *(long long*)0x408820
$1 = 540
```

`540 & 0xFF = 0x1c` → **XOR 目标是 0x1c**

### 第四步：编写 Shellcode

CPU 跳到 buf 后，我们需要它做这些事：

1. 调用 `GenerateRandomNumber(0x400)` — 更新随机数
2. 把 `rand_div` 存入全局变量 `result`（地址 `0x4087f8`）
3. 跳回主程序 `0x4018a0`，让后续检查通过

逐行翻译成机器码：

| 汇编指令 | 机器码 | 含义 |
|----------|--------|------|
| `mov edi, 0x400` | `bf 00 04 00 00` | 参数 = 0x400 |
| `movabs rax, 0x4016ad` | `48 b8 ad 16 40 00 00 00 00 00` | GenerateRandomNumber 地址 |
| `call rax` | `ff d0` | 调用函数 |
| `movabs rax, 0x408820` | `48 b8 20 88 40 00 00 00 00 00` | &rand_div |
| `mov rax, [rax]` | `48 8b 00` | 读取 rand_div |
| `movabs rcx, 0x4087f8` | `48 b9 f8 87 40 00 00 00 00 00` | &result |
| `mov [rcx], eax` | `89 01` | result = rand_div |
| `push 0x4018a0` | `68 a0 18 40 00` | 目标地址压栈 |
| `ret` | `c3` | 跳转到 0x4018a0 |

> **为什么用 push + ret？** 这是实现绝对地址跳转的通用技巧。`jmp` 只能相对跳转，距离可能不够。

### 第五步：拼 buf 并修正 XOR

Shellcode 只有几十字节，buf 有 256 字节。多出来的位置填 0，然后用一个"修正字节"让整体 XOR = 0x1c。

```python
import struct

# 拼接 shellcode
sc  = b"\xbf\x00\x04\x00\x00"
sc += b"\x48\xb8" + struct.pack("<Q", 0x4016ad)
sc += b"\xff\xd0"
sc += b"\x48\xb8" + struct.pack("<Q", 0x408820)
sc += b"\x48\x8b\x00"
sc += b"\x48\xb9" + struct.pack("<Q", 0x4087f8)
sc += b"\x89\x01"
sc += b"\x68" + struct.pack("<I", 0x4018a0)
sc += b"\xc3"

# 放入 256 字节 buf
buf = bytearray(256)
buf[:len(sc)] = sc

# 计算当前 XOR 值
xor_val = 0
for b in buf: xor_val ^= b

# 在 shellcode 后面放一个修正字节
target = 0x1c
buf[len(sc)] = xor_val ^ target

# 输出答案
print(buf.hex())
```

**原理**：假设当前 XOR = X，放一个 `X ^ 0x1c` 进去，总体就变成 `X ^ (X ^ 0x1c) = 0x1c`。

### 第六步：（可选）触发隐藏彩蛋

程序里有个死代码函数 `phase_secret`（地址 `0x401a8b`），永远不会被正常调用。你可以在 shellcode 里加两行去调用它：

```
mov edi, 0                   # bf 00 00 00 00
movabs rax, 0x401a8b         # 48 b8 8b 1a 40 00 00 00 00 00
call rax                     # ff d0
```

这样运行时会多输出一行：`不可能的...不可能的...指令和数据的世界已经混乱...SOS...`

加在 `mov [rcx], eax` 之后、`push 0x4018a0` 之前。别忘了重新计算修正字节。

## 通用方法论

每个 Phase 的破解流程：

```
设断点 → 运行 → 查 rand_div → 读反汇编理解约束 → 算答案
```

核心技巧：

1. **`p *(long long*)0x408820`** — 这条命令查 `rand_div`，是你用得最多的
2. **`x/s $rdi` / `x/s $rsi`** — 查看字符串参数，Phase 1 一招秒杀
3. **`x/i $rax`** — 跳转表分发时看实际跳转目标，避免跳转表陷阱
4. **边解边写答案文件** — 每解出一关就写入，下一关自动通过前面的

Phase 5 特殊：

- 需要手写 x86-64 机器码（shellcode）
- 用一个修正字节搞定 XOR 校验
- `push + ret` 实现绝对跳转
- 结构通用，不同学号只需改 XOR 目标值
