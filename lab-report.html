1. 实验是什么？

要实现的 7 个函数
eval · builtin_cmd · do_bgfg · waitfg
sigchld_handler · sigint_handler · sigtstp_handler
骨架已提供的内容
main 读写循环 · parseline 命令行解析
addjob / deletejob / listjobs / fgpid 等作业列表操作

2. 我的实现过程

第一步：理解骨架 + 编译环境
先 make 保证骨架编译通过（此时 ./tsh 能启动但任何外部命令都执行不了）。 阅读 main 了解主循环结构：注册三个信号 handler → 初始化 job list → 循环 fgets → eval → fflush。
第二步：实现 builtin_cmd
最简单的起点——识别 quit / jobs / bg / fg 四种内置命令。 返回 1 表示已处理，返回 0 交给 eval 去 fork。
第三步：实现 eval + waitfg
整个 shell 的核心。fork 子进程 → 子进程 setpgid(0,0) 建独立进程组 → execve 替换程序映像；父进程 addjob 后根据前台/后台决定 wait 还是立即返回。 关键：fork 前屏蔽 SIGCHLD，addjob 后解除，消除竞态条件。
第四步：实现三个信号 handler
先写 sigchld_handler——用 waitpid(-1, &status, WNOHANG|WUNTRACED) 在 while 循环中回收所有僵尸/停止的子进程。再写 sigint_handler 和 sigtstp_handler——向 fgpid(jobs) 对应进程组发送 kill(-pid, SIGINT/TSTP)。
第五步：实现 do_bgfg
处理 bg %n / fg %n / bg PID / fg PID 四种格式，含完整错误处理。用 kill(-pid, SIGCONT) 向整组发送继续信号，然后 改状态并决定是否 wait。
第六步：逐 trace 调试
用 ./sdriver.pl -t traceXX.txt -s ./tsh -a "-p" 逐个跑测试， 与 tshref.out 对比。遇到的主要 bug：sigchld_handler 里 先 deletejob 后 pid2jid 导致 jid=0、错误信息格式不匹配 trace14、以及 ps 输出的环境噪声。

3. 核心设计决策（验收重点）

① 进程组隔离 — setpgid(0,0)
每个前台任务放入独立进程组。这样 kill(-pgid, sig) 只影响该任务（及其 fork 出的子进程）， shell 自身和其他后台任务不受影响。如果缺少这行，Ctrl-C 会直接把 shell 也杀掉。
② SIGCHLD 临界区保护
fork 前 sigprocmask(SIG_BLOCK, &mask, &prev) 屏蔽 SIGCHLD → fork → 父进程 addjob → sigprocmask(SIG_SETMASK, &prev, NULL) 解除屏蔽。
如果不屏蔽：子进程可能秒退 → 内核发 SIGCHLD → handler 执行 deletejob → 但父进程还没 addjob → jobs 列表出现永远删不掉的"幽灵任务"。
③ kill(-pid, sig) 向进程组广播
负号 PID 表示"以该 PID 为组长的整个进程组"。对于 mysplit（会 fork 子进程的测试程序）， 必须用负号才能确保父子进程同时收到信号，否则只能杀/停父进程，子进程变成孤儿。
④ sigsuspend 而非 sleep(1)
waitfg 中不调用 waitpid（回收已在 handler 完成）， 而是用 sigsuspend(&mask) 原子地挂起等待任意信号。 相比忙等，响应即时且不浪费 CPU。
⑤ handler 中 while 循环 + errno 保护
内核会合并信号——一次 SIGCHLD 可能对应多个子进程退出。用 while 而非 if 确保全部回收。保存/恢复 errno 防止 handler 污染主流程中被中断的系统调用。

4. 七个函数的设计逻辑

4.1 builtin_cmd(argv)

判断 argv[0] 是否为内置命令。是 → 执行并返回 1；否 → 返回 0。

if      (!strcmp(argv[0], "quit")) exit(0);
else if (!strcmp(argv[0], "&"))    return 1;   // 无意义的单独 &
else if (!strcmp(argv[0], "jobs")) { listjobs(jobs); return 1; }
else if (!strcmp(argv[0], "bg") || !strcmp(argv[0], "fg")) { do_bgfg(argv); return 1; }
else return 0;  // 不是内置命令

4.2 eval(cmdline)

主执行入口。解析命令行 → 判断内置命令 → 非内置则 fork+exec。

parseline(buf, argv);                    // 解析，返回 bg
if (argv[0] == NULL) return;
if (builtin_cmd(argv)) return;

sigprocmask(SIG_BLOCK, &mask, &prev);   // ★ 屏蔽 SIGCHLD
if ((pid = fork()) == 0) {
    sigprocmask(SIG_SETMASK, &prev, 0); // 子进程恢复屏蔽
    setpgid(0, 0);                       // ★ 独立进程组
    execve(argv[0], argv, environ);      // 替换程序映像
}
addjob(jobs, pid, bg ? BG : FG, cmdline);
sigprocmask(SIG_SETMASK, &prev, 0);     // ★ 解除屏蔽

if (!bg) waitfg(pid);                    // 前台：挂起等待
else printf("[%d] (%d) %s", jid, pid, cmdline); // 后台：打印后立即返回

4.3 waitfg(pid)

sigset_t mask;
sigemptyset(&mask);
while (fgpid(jobs) == pid)
    sigsuspend(&mask);   // 原子挂起，等任意信号到来后检查

4.4 sigchld_handler(sig)

int olderr = errno;
while ((pid = waitpid(-1, &status, WNOHANG | WUNTRACED)) > 0) {
    if (WIFEXITED(status))
        deletejob(jobs, pid);              // 正常退出，删
    else if (WIFSIGNALED(status)) {
        printf("Job [%d] (%d) terminated by signal %d\n", ...);
        deletejob(jobs, pid);              // 先打印，再删！
    } else if (WIFSTOPPED(status)) {
        jp->state = ST;                    // 改状态，不删
        printf("Job [%d] (%d) stopped by signal %d\n", ...);
    }
}
errno = olderr;  // ★ 恢复 errno

4.5 do_bgfg(argv)

// 1. 参数检查：空 → 报错；%n → getjobjid；数字 → getjobpid；其他 → 报错
// 2. kill(-jobp->pid, SIGCONT)  // ★ 向整组发 SIGCONT
// 3. fg → jobp->state = FG → waitfg(jobp->pid)
//    bg → jobp->state = BG → printf("[%d] (%d) %s", ...)

4.6 sigint_handler(sig)

pid = fgpid(jobs);
if (pid != 0) kill(-pid, SIGINT);  // 有前台任务才发，防止误杀 shell

4.7 sigtstp_handler(sig)

pid = fgpid(jobs);
if (pid != 0) kill(-pid, SIGTSTP); // 发给前台进程组，子进程暂停后内核触发 SIGCHLD

5. 作业状态机

整个 shell 的作业管理围绕四个状态转换展开：

              fork + exec
 ┌─────────────────────────────┐
 │                             ▼
 │                          ┌──────┐
 │         Ctrl-Z           │  FG  │ ← 前台（最多 1 个）
 │       ┌───────────────── │      │
 │       │                  └──────┘
 │       ▼                     ▲
 │   ┌──────┐   bg %n         │  fg %n
 └───│  ST  │────────────────►├──────┐
     │ 暂停 │                 │  BG  │ ← 后台（可多个）
     └──────┘                 └──────┘
         ▲                        │
         └────── Ctrl-Z ──────────┘
状态含义如何进入
FG前台运行fork 非 & 命令；fg %n
BG后台运行fork & 命令；bg %n
ST已停止Ctrl-Z 暂停前台任务
UNDEF空槽位deletejob 后清除

7. 踩过的坑

问题现象根因 & 解决
Ctrl-C 杀死 shell trace06 一跑 shell 直接退出 没调 setpgid(0,0)，子进程和 shell 同进程组。
在子进程 execve 前加 setpgid(0,0) 解决。

8. 实验心得

这个 lab 本质上是在训练「信号 + 进程组 + 临界区」三者的协同能力：

进程组让 Ctrl-C / Ctrl-Z 能精准命中前台任务而不波及 shell 自身； 信号机制让 shell 能异步感知子进程的退出和停止，无需轮询； 临界区保护（fork 前屏蔽 SIGCHLD）防止 job list 与子进程实际状态不一致。

这是我第一次从系统调用层面理解 Shell 的工作原理，对 fork / execve / waitpid / kill / sigprocmask / sigsuspend 等关键系统调用有了直观的认知。理解最深刻的一点是：并发竞态不只出现在多线程中， 信号处理与主流程的交叉执行同样构成并发，需要临界区保护。
