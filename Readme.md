# Lab7: Cache 模拟器实验

## 注意事项

- **只能修改 `Cache.c` 文件**，其他文件请勿修改！
- Data Cache 最大只能使用 **16KB** 的数据存储空间。

---

## 一、实验目标

实现一个高命中率的 Cache 系统。实验框架（`CacheHelper.c`）会读入程序的内存访问记录（trace 文件），然后调用你写的 Cache 函数来模拟每次访问是命中还是缺失。

最终目标是：**让尽可能多的访问在 Cache 中命中，减少访问内存的次数。**

---

## 二、什么是 Cache？（背景知识）

### 2.1 为什么需要 Cache？

CPU 速度远快于内存。如果 CPU 每次都直接访问内存，会浪费大量时间等待。Cache 是一个靠近 CPU 的小容量高速存储，存放最近使用过的数据。

### 2.2 Cache 的基本原理

把内存看作一个巨大的数组，Cache 只能存放其中一小部分。每次 CPU 要读写数据时：

1. **先查 Cache**：如果数据在 Cache 中 → **命中（Hit）**，直接使用，很快！
2. **不在 Cache 中** → **缺失（Miss）**，需要从内存加载到 Cache，较慢。

### 2.3 直接映射 vs 组相联

这是本次实验的核心。假设 Cache 有 256 个位置可以放数据：

| 方式 | 说明 | 缺点 |
|------|------|------|
| **直接映射** | 内存地址只能放到 Cache 中固定的 1 个位置 | 两个地址映射到同一位置时会互相淘汰（冲突缺失） |
| **2路组相联** | 每个位置可以放 2 个数据，淘汰最久没用的那个 | 实现稍复杂 |
| **4路组相联** | 每个位置可以放 4 个数据 | 更灵活，冲突更少 |
| **全相联** | 任意数据可以放到 Cache 中任意位置 | 硬件成本最高 |

**路数越多，冲突越少，命中率越高**（但硬件成本也越高）。

### 2.4 地址的切分

Cache 把内存地址切分为三部分：

```
|      Tag       |   Set Index   |  Block Offset  |
|   (标识是哪个块)  | (映射到哪一组) | (块内偏移)      |
```

- **Block Offset**：每个 Cache 行存 64 字节数据，offset 指定读写的第几个字节（6 位）
- **Set Index**：决定这个地址映射到 Cache 的哪一组
- **Tag**：同组内用来区分不同内存地址的标识

### 2.5 LRU 替换策略

当一组中所有位置都满了，需要淘汰一个。LRU（Least Recently Used，最近最少使用）策略：**淘汰最久没被访问的那一行**。

实现方式：每行记录一个"上次访问时间戳"，每次访问时更新。淘汰时选时间戳最小的。

## 三、实现方案

### 3.1 整体架构：四级缓存层次 + 硬件预取

```
CPU 访问
  │
  ▼
┌──────────────────────────┐
│  L1 Data Cache (16KB)    │  8路组相联, 64B行, LRU
│  数据缓存 + Next-Line预取 │  ← 最快，容量最小
└────────┬─────────────────┘
         │ Miss (未命中)
         ▼
┌──────────────────────────┐
│  Victim Cache (4KB)      │  全相联, 64B行, LRU
│  牺牲缓存                 │  ← 缓存被 L1 淘汰的行
└────────┬─────────────────┘
         │ Miss
         ▼
┌──────────────────────────┐
│  L2 Unified Cache (1MB)  │  8路组相联, 64B行, LRU
│  统一缓存                 │  ← 容量大，数据和指令共享
└────────┬─────────────────┘
         │ Miss
         ▼
┌──────────────────────────┐
│  Memory (内存)            │  ← 最慢
└──────────────────────────┘

同时还有:
┌──────────────────────────┐
│  L1 Inst Cache (16KB)    │  8路组相联, 64B行, LRU
│  指令缓存 + Next-Line预取 │  ← 只读，Miss 时查 L2 → Memory
└──────────────────────────┘
```

### 3.2 各级缓存参数

| 缓存 | 容量 | 行大小 | 组数 | 路数 | 替换策略 | 预取 |
|------|------|--------|------|------|----------|------|
| L1 Data | 16KB | 64B | 32 | 8 | LRU | +1, +2行 |
| Victim | 4KB | 64B | - (全相联) | 64 | LRU | - |
| L2 Unified | 1MB | 64B | 2048 | 8 | LRU | - |
| L1 Inst | 16KB | 64B | 32 | 8 | LRU | +1, +2行 |

### 3.3 关键设计点

1. **8路组相联**：相比原始直接映射，8路允许同一组存放 8 个不同地址的数据，大幅减少冲突缺失
2. **Victim Cache**：L1 淘汰的行不会直接丢弃，而是放入 Victim Cache。下次再访问时可以直接从 Victim 找回
3. **脏位（Dirty Bit）**：记录某一行是否被修改过。只有修改过的行淘汰时才需要写回内存
4. **独占缓存模型**：数据同一时间只存在于一级缓存中（L1 或 Victim 或 L2），最大化有效容量
5. **写回策略（Write-Back）**：写入时只修改 Cache，不立即写内存。淘汰脏行时才写回
6. **硬件预取（Next-Line Prefetcher）**：未命中时提前载入后续 2 行到 L1，预取行标记最低淘汰优先级

### 3.4 访问流程（数据访问）

```
收到一个访存请求（读/写/修改）
  │
  ├─ 在 L1 Data Cache 中查找
  │   ├─ 命中 → 更新 LRU 时间戳，执行读/写，返回 HIT
  │   └─ 未命中 ↓
  │
  ├─ 在 Victim Cache 中查找
  │   ├─ 命中 → 取出数据，放入 L1（被淘汰的 L1 行放入 Victim）
  │   └─ 未命中 ↓
  │
  ├─ 在 L2 Cache 中查找
  │   ├─ 命中 → 取出数据，放入 L1（同上）
  │   └─ 未命中 ↓
  │
  ├─ 从 Memory 加载数据到 L1
  │
  ├─ 预取后续 2 行到 L1（标记最低优先级）
  │
  └─ 执行读/写操作，返回 MISS
```

淘汰链：L1 淘汰的行 → Victim Cache → Victim 满则淘汰到 L2 → L2 满则脏行写回 Memory。

## 五、具体操作步骤

### 5.1 环境准备

```bash
# 安装依赖（只需要执行一次）
sudo apt install libzstd-dev zstd

# 如果你以后想自己生成 trace 文件，也装一下 valgrind
sudo apt install valgrind
```

### 5.2 编译运行

```bash
# 进入实验目录
cd lab7/

# 编译（每次修改 Cache.c 后都要重新编译）
make

# 运行单个 trace
./Cache traces/long.trace.zst

# 一键测试所有 trace（推荐）
./test_all.sh
```

### 5.3 看懂输出

运行后你会看到类似输出：

```
[SimTrace] |  Data Cache命中率   |  98.31%   |   ← 这个数字越高越好！
[SimTrace] |  Inst Cache命中率   |  0.00%    |   ← 指令缓存命中率
[main] Cache模拟成功完成                         ← 出现这个说明结果正确
```

- **如果看到"关键错误"**：说明你的 Cache 实现有 bug，读出的数据和内存中的不一致
- **如果看到"Cache模拟成功完成"**：说明实现正确，可以关注命中率

## 七、自行生成 trace 文件（可选）

如果你想用自己的程序生成 trace 来测试：

```bash
# 1. 用 valgrind 记录程序的所有内存访问
valgrind --tool=lackey -v --trace-mem=yes --log-file=ls.trace ls -l

# 2. 压缩为 zst 格式
zstd ls.trace -o ls.trace.zst

# 3. 用你的 Cache 跑这个 trace
./Cache ./ls.trace.zst
```

你可以替换 `ls -l` 为任何你想测试的程序，比如 `cat`、`grep`、`gcc` 等。
